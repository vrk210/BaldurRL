# Task 3: Reproducible encounter trial specification and offline analyzer

Read IMPLEMENTATION_PLAN.md, integration/schema.py, serialization.py, trace.py, commands.py and command_transport.py, plus docs/BG3_ACTION_EXECUTION.md live validation plan. Own only integration/encounter_trial.py, bg3/trials/*, tests/test_encounter_trial.py, docs/windows/ENCOUNTERS.md. No transport/schema/combat/agents changes.

## Scope

Build the preparation/analysis harness for one human attack, one autonomous attack, and a resource-exhaustion rejection. It consumes existing observations and explicit operator evidence; it never performs game actions, assumes BG3 costs, or manufactures game evidence. Runtime stdlib only. Expose `python -m integration.encounter_trial init PATH --kind human_attack|autonomous_attack|resource_rejection` to produce a reviewable versioned template; and `... analyze TRIAL.json --records DIR [--session-dir DIR] [--output REPORT.json]`. Reject existing init destination, unknown fields/types/versions and malformed IDs/sequence bounds with helpful errors. Document template edits required before analysis.

## Minimal trial v1

Fields: schema_version, trial_id, kind, capture_origin (unknown/synthetic/live_operator_reported), actor_entity_id, target_entity_id, ability_id (original opaque ID), combat_id (nullable), before_sequence, after_sequence, story_action_id (nullable; zero valid), command_id (nullable), expected_resource_deltas array keyed by actual resource_id + nullable level + numeric expected delta, completion_evidence (nullable explicit source/reason for manual completion observation), rejection_evidence (nullable explicit source/reason for observed rejection), operator-reported game/SE versions and notes. Templates leave facts null/empty and analyzer must report INCONCLUSIVE rather than fill simulator defaults. Exact representation of evidence objects may be simple `{source, reason}`; document strict field sets. At least one measured expected resource delta is required for a verified resource-consumption check. Do not interpret empty expectation list as proof of correct costs.

## Analysis semantics

Read observations once and validate exact collection. Explicit before/after sequences must reference snapshots in this session, in order; gaps/invalid files are errors or FAIL with precise evidence. Match actor, ability, target and combat when known; do not silently accept a mismatch. Collect raw events across the explicit before/after window, which can contain intermediate snapshots; do not assume one snapshot interval is one action. Generic and targeted spell events with same non-null StoryActionID are one attempted action, not duplicates. Distinct IDs or missing-ID multiple actions are ambiguous. Use existing conservative helpers when useful. A miss counts as execution, not a failed attack. UsingSpell / an animation / HP delta alone is not completion proof. Completion requires explicit operator evidence for human trials or a matching resolved command acknowledgement plus valid post-execution snapshot confirmation for autonomous trials; acceptance alone is insufficient. Link command by explicit command_id and verify its intent against trial, not automatic timestamp/StoryActionID guessing. Unsupported/unavailable evidence remains INCONCLUSIVE.

Compute resource deltas from actual before/after actor ResourceValue entries by ID/level. Missing resource either side is unknown; never zero-fill. Compare against caller-declared measured-control expectations (no preset action costs). Verify bounds and explain whether turn refresh could confound comparison; a turn boundary in the window makes cost attribution INCONCLUSIVE. For resource_rejection, require explicit rejection evidence, no contradictory completed/attempted action evidence, and available resource measurements; absence of events alone is not proof of rejection. Wrong actor/target/ability, extra distinct controlled actions, contradictory outcome or resource deltas => FAIL with evidence. Do not infer damage on miss or count critical+damage notifications as extra attacks.

Output report schema_version=1 with PASS/FAIL/INCONCLUSIVE, individual check statuses/reasons/supporting record sequences, observed resource deltas, provenance including capture_origin, and `live_verified=false` (tool verifies a bounded trace claim, never certifies BG3 readiness). A valid synthetic fixture may pass offline checks but must stay labeled synthetic. CLI exit 0 PASS, 1 FAIL, 2 INCONCLUSIVE or usage/validation error (document distinction in JSON). Retain raw stream unchanged. No reward labels/behavior cloning assembly unless evidence already sufficient; no neural models.
