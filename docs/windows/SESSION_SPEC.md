## Implement

A stdlib CLI `python -m integration.session_runner --capture-root PATH --archive-root PATH [--once] [--poll-interval 0.5] [--game-version TEXT] [--se-version TEXT] [--code-revision TEXT]`. Capture root is exactly the parent of collector GUID session directories (e.g. .../Script Extender/BaldurRL/H0), not guessed globally. Discover each session containing staging/. Automatically handle additional sessions on later polls without mixing sequence namespaces. Publish ready files to that session's records/ using publish_ready. Archive to <archive-root>/<session-id>/ with separate staging/, records/, diagnostics/ and a versioned manifest/health report. Preserve actual bytes and source identity. Reject source/archive overlap and path traversal; do not combine a reused session ID from a different source. Never silently overwrite differing immutable published records. Version/build arguments are operator-reported and must be labeled as such; unknown stays null. Include code revision (explicit or safe git lookup), collector source hashes, origin paths, and per-session stats. Do not record environment variables or credentials.

Use a cooperating single-runner lock per source session; a second runner must fail visibly. Do not automatically delete stale locks; explain recovery. Once mode deterministic and unit-testable; watch polls until Ctrl-C. Errors must identify session/path and fail visibly without silently dropping records. Partial marker is incomplete, not corruption; completed corrupt payload is an error. Document no exactly-once or power-loss durability guarantee. No network or OS watcher framework.

Health derives from one read_all collection validated with validate_sequence: snapshot/event count, first/last sequences, gaps, latest record kind, latest snapshot sequence, selected/active entity known/unknown, known resource/ability/candidate counts. Empty candidates are unknown enumeration, not no legal actions. Health must say offline schema validity is separate from live completeness/decision readiness. Do not infer LEGAL, alive from HP, complete participants, completion, or selected actor from host identity. Archive raw incomplete staging as diagnostic bytes, but never promote it to records. Do not archive arbitrary entire game directories or unrelated mods/logs automatically.

Read-only probes: turn existing verified-source snippets in docs/BG3_ACTION_EXECUTION.md into bg3/probes/server_inspect.lua plus README. Probe loaded actor component names and optionally SpellBook/SpellBookPrepares/ActionResources/TurnBased only after checking existence. API/query errors visible with structured diagnostics; avoid retaining engine userdata beyond callback scope. Save JSON diagnostics using Ext.IO.SaveFile/Ext.DumpExport only where supported, else clear console output. Actual selected actor is explicit input; never assume host equals selected. No hardcoded BG3 spell/resource/entity IDs or any game mutation. Include reported SE/game versions if exported functions exist, and null/error if not. No collector edits needed. Never inject input or touch cast-request queues.

Research already done: Ext.IO.SaveFile creates missing parent dirs; usual root LOCALAPPDATA/Larian Studios/Baldur's Gate 3/Script Extender. Engine userdata lifetime is callback scoped; reacquire per call. Sources: https://github.com/Norbyte/bg3se/blob/main/Docs/API.md#io and current docs/BG3_ACTION_EXECUTION.md read-only Windows inspection section. Ask primary if missing facts; do not invent APIs.
