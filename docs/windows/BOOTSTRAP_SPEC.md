## Implement

A stdlib Python CLI `python -m integration.windows_preflight --game-dir PATH [--script-extender-root PATH] [--modsettings PATH] [--json]` and small testable functions. Paths must be explicit or derived only from an explicitly supplied game directory / documented LOCALAPPDATA default. Doctor is read-only; do not auto-install or change files. Validate repo mod source layout, meta.lsx UUID and Config.json syntax; game executable/bin identification (accept game root with bin, or explicit bin); DWrite.dll presence; ScriptExtenderSettings.json JSON object and CreateConsole/LogRuntime enabled; supplied modsettings.lsx activation by actual module UUID; staging root existence. Distinguish missing/error from present-but-live-unverified, and unsupported/non-Windows environment. File presence is never a successful mod-load/API/legality check. Report each check status, evidence/path, next action, and overall static readiness; output schema_version=1 and live_verified=false. Missing configuration is a clear nonzero status; malformed JSON/XML is a helpful error without crashing.

PowerShell bootstrap: supports `-Python` and explicit venv path, creates a local venv, installs ONLY optional harness test dependencies if requested via `-InstallTestDependencies`, invokes doctor with forwarded paths, and propagates exit codes. Core integration runs on stdlib; no Torch/PPO requirement. Do not download BG3SE/LSLib automatically, activate mods, overwrite existing settings, or change registry/execution policy. Resolve repo root from script location and quote paths properly. Pinned optional test dependencies from the tested environment: pytest==9.1.1, lupa==2.8 (Python >=3.11). If compatibility with platform wheel remains untested, say so.

PowerShell packaging: explicit `-DivinePath`, `-OutputPath`; invocation `divine.exe --game bg3 --action create-package --source <repo>/bg3/h0 --destination <absolute output.pak>`. Source includes Mods at the package root; do not package only Lua or the parent bg3 directory. Validate inputs, reject output beneath source, refuse overwrite unless explicit -Force, check native exit code and nonempty output, write a SHA-256 source/output manifest beside package. Do not claim the external tool invocation has been tested on Windows. Provide `-DryRun` that prints the argv/source manifest without invoking Divine or creating a fake .pak. Actual packaging should stage into a temporary output path to avoid destroying an existing package on converter failure if -Force is used.

Research already done: Norbyte/lslib Divine/CLI/CommandLineArguments.cs and CommandLineActions.cs establish --game bg3, --action create-package, --source, --destination. Source: https://github.com/Norbyte/lslib/blob/master/Divine/CLI/CommandLineArguments.cs . BG3SE settings and installation sources are already linked in bg3/h0/README.md. Do not do new research; ask primary if facts are missing.
